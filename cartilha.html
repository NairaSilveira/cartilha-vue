Cartilha de Padrões e Abordagens de Projeto no Vue.js

Esta cartilha foi elaborada como parte das atividades de extensão universitária e tem como objetivo apoiar estudantes e desenvolvedores iniciantes na compreensão dos principais padrões de projeto aplicados ao framework Vue.js. Espera-se que este material contribua para o aprendizado dos conceitos apresentados e sirva como fonte de consulta durante o desenvolvimento de aplicações.

📚 Sobre esta cartilha

O material apresenta conceitos e exemplos que podem contribuir para o desenvolvimento de aplicações mais organizadas, reutilizáveis e fáceis de manter.

Introdução

Esta cartilha tem como objetivo apresentar alguns dos principais padrões de projeto utilizados no desenvolvimento de software, com foco em sua aplicação no framework Vue.js. Embora os exemplos sejam desenvolvidos utilizando essa tecnologia, os conceitos abordados podem ser aplicados em diferentes linguagens de programação e frameworks.

Considerando a constante evolução da área de desenvolvimento de software, existem diversos padrões de projeto além dos apresentados neste material. Assim, esta cartilha não pretende esgotar o assunto, mas fornecer uma base para compreender como essas soluções podem contribuir para o desenvolvimento de aplicações mais organizadas, reutilizáveis e de fácil manutenção.

Mas afinal, o que são Padrões de Projeto?

Padrões de projeto (Design Patterns) são soluções consolidadas para problemas recorrentes encontrados durante o desenvolvimento de software. Em vez de fornecerem um código pronto, eles descrevem formas eficientes de estruturar a aplicação, facilitando a reutilização de soluções, a manutenção do código e a comunicação entre desenvolvedores. Quando utilizados de maneira adequada, contribuem para a construção de sistemas mais flexíveis, organizados e escaláveis.

Por que utilizar Padrões de Projeto?

O desenvolvimento de software envolve desafios que costumam se repetir em diferentes projetos, como organizar o código, facilitar sua manutenção e permitir que novas funcionalidades sejam adicionadas sem comprometer o funcionamento da aplicação. Nesse contexto, os padrões de projeto oferecem soluções consolidadas para esses problemas, auxiliando os desenvolvedores na construção de sistemas mais consistentes e bem estruturados.

A adoção desses padrões contribui para a criação de aplicações mais organizadas, reduzindo a duplicação de código e favorecendo a reutilização de componentes. Além disso, eles promovem uma melhor separação de responsabilidades entre as partes do sistema, tornando o código mais legível, flexível e simples de manter ao longo do tempo.

Outro benefício importante é a padronização das soluções empregadas durante o desenvolvimento. Como muitos padrões de projeto são amplamente conhecidos pela comunidade de desenvolvedores, sua utilização facilita a comunicação entre os membros da equipe e torna mais simples a compreensão da arquitetura da aplicação por todos os envolvidos no projeto.

Entretanto, é importante destacar que os padrões de projeto devem ser utilizados de maneira consciente. Sua utilização deve estar alinhada às necessidades do sistema, evitando o emprego desnecessário de soluções que possam aumentar a complexidade do código. Quando empregados de forma adequada, os padrões tornam o desenvolvimento mais eficiente e contribuem para a qualidade, a escalabilidade e a manutenção das aplicações.

📌 Resumindo...

Ao utilizar padrões de projeto, o desenvolvedor consegue:

  • Organizar melhor a estrutura da aplicação;
  • Reutilizar soluções já consolidadas;
  • Reduzir o acoplamento entre os componentes do sistema;
  • Facilitar a manutenção e a evolução do código
  • Melhorar a comunicação entre os membros da equipe;
  • Desenvolver sistemas mais flexíveis, reutilizáveis e escaláveis.
01

Configuração do Script (<script setup>)

No contexto do Vue.js, a forma de estruturar nosso código evoluiu muito com a chegada da Composition API. Para aplicarmos os padrões modernos que veremos a seguir, a base técnica fundamental é o uso do (<script setup>).

O que é?

A Configuração do Script (<script setup>) é um recurso introduzido no Vue 3 que simplifica a escrita de componentes desenvolvidos utilizando a Composition API. Em vez de declarar manualmente a função setup(), esse recurso permite que todo o código seja escrito diretamente dentro da tag (<script setup>), tornando o componente mais limpo, objetivo e fácil de compreender.

Além de reduzir a quantidade de código necessária para criar um componente, essa abordagem melhora a organização do projeto e facilita a manutenção da aplicação, principalmente em sistemas compostos por diversos componentes reutilizáveis.

Como funciona?

Ao utilizar (<script setup>), todas as variáveis, funções e objetos declarados no script tornam-se automaticamente disponíveis para utilização no template do componente. Dessa forma, não é necessário retornar manualmente essas informações, como ocorre na utilização tradicional da função setup().

Essa simplificação reduz a quantidade de código repetitivo e torna o desenvolvimento mais produtivo, permitindo que o desenvolvedor concentre seus esforços na implementação das funcionalidades da aplicação.

Quando utilizar?

A utilização de (<script setup>) é recomendada para novos projetos desenvolvidos com Vue 3 ou durante a modernização de aplicações existentes que utilizam a Composition API. Essa abordagem é especialmente útil quando se deseja escrever componentes menores, mais organizados e de fácil manutenção.

Embora seja possível utilizar a sintaxe tradicional baseada na função setup(), a configuração por meio de (<script setup>) é atualmente a abordagem recomendada pela equipe responsável pelo Vue.js devido à sua simplicidade e melhor desempenho durante a compilação.

Exemplo prático

Imagine um componente responsável por exibir uma saudação ao usuário. 

<script setup>
import { ref } from 'vue'

const nome = ref('Maria')

function alterarNome() {
    nome.value = 'Visitante'
}
</script>

<template>
    <div>
        <h2>Olá, {{ nome }}!</h2>

        <button @click="alterarNome">
            Alterar nome
        </button>
    </div>
</template>

Nesse exemplo, a variável nome e a função alterarNome() podem ser utilizadas diretamente no template, sem que seja necessário retorná-las explicitamente.

Vantagens

  • Reduz a quantidade de código necessária para criar componentes;
  • Elimina a necessidade de declarar a função setup();
  • Facilita a leitura e a organização do código;
  • Possui melhor integração com a Composition API;
  • Favorece a reutilização de lógica por meio de composables;
  • Oferece melhor otimização durante a compilação do projeto.
🚨⚠️ Atenção

Embora <script setup> simplifique o desenvolvimento, é importante manter uma boa organização do código. Componentes com muitas responsabilidades podem se tornar difíceis de compreender, mesmo utilizando essa abordagem. Sempre que possível, recomenda-se dividir funcionalidades complexas em componentes menores ou em composables.

📌 Resumindo...

O <script setup> permite:

  • Escrever componentes com menos código;
  • Utilizar variáveis e funções diretamente no template;
  • Simplificar a Composition API;
  • Melhorar a organização dos componentes;
  • Facilitar a manutenção do projeto.
02

Componentes

No Vue.js, a interface do usuário é construída através de Componentes. Em vez de criarmos páginas inteiras em um único arquivo gigante, dividimos a interface em blocos menores, independentes e reutilizáveis (como um cabeçalho, um botão ou uma lista de itens).

O que é?

Componentes são os blocos de construção fundamentais das aplicações Vue.js. Eles permitem acoplar marcação (HTML), lógica (JavaScript) e estilos (CSS) em uma única estrutura coesa. Em uma aplicação típica, quase todos os elementos visuais da interface fazem parte de um componente. Na prática, a aplicação é formada por uma árvore de componentes aninhados em uma hierarquia, variando desde objetos JavaScript simples até Single-File Components (SFCs), os tradicionais arquivos .vue

Como funciona?

Os componentes encapsulam partes da interface que possuem sua própria estrutura e comportamento, permitindo que sejam desenvolvidos e mantidos de forma independente. Por meio de Props (propriedades), componentes pais podem enviar dados para componentes filhos, possibilitando a reutilização de uma mesma estrutura com diferentes informações.

Além disso, recursos como ref() e reactive() permitem gerenciar dados reativos, fazendo com que a interface seja atualizada automaticamente quando esses valores são alterados.

Quando utilizar?

A criação e a extração de componentes devem ser utilizadas para promover a reutilização e facilitar a manutenção em aplicações de médio a grande porte. Uma boa regra prática é separar um trecho da interface em um novo componente sempre que ele for utilizado diversas vezes (como botões, painéis ou avatares) ou quando for complexo o suficiente por si só (como um formulário de comentários ou uma seção inteira de um aplicativo).

Exemplo prático

Considere uma aplicação desenvolvida para o gerenciamento de projetos de uma feira científica. Nesse contexto, pode ser necessário apresentar diversas informações de projetos em diferentes partes da aplicação. Para evitar a repetição da mesma estrutura de código, podemos criar um componente responsável por exibir os dados de cada projeto.

O componente ProjetoCard.vue pode ser definido da seguinte maneira:

<script setup>

defineProps({
    titulo: String,
    autor: String,
    categoria: String
})

</script>

<template>

    <div class="projeto-card">

        <h2>{{ titulo }}</h2>

        <p>
            <strong>Autor:</strong>
            {{ autor }}
        </p>

        <p>
            <strong>Categoria:</strong>
            {{ categoria }}
        </p>

    </div>

</template>

Depois de criado, esse componente pode ser utilizado por um componente pai, como App.vue, passando diferentes informações por meio das propriedades:

<script setup>
import ProjetoCard from './components/ProjetoCard.vue'
</script>

<template>

    <div class="projeto-card">
        <h1>Projetos da Feira Científica</h1>
        <ProjetoCard
        titulo="Sistema de Irrigação Inteligente"
        autor="Ana Souza"
        categoria="Tecnologia"
        />

        <ProjetoCard
        titulo="Análise da Qualidade da Água"
        autor="Carlos Oliveira"
        categoria="Meio Ambiente"
        />
        
        <ProjetoCard
         titulo="Aplicação de Energia Solar"
         autor="Mariana Santos"
         categoria="Sustentabilidade"
        />
     </div>

</template>

Nesse exemplo, o componente ProjetoCard possui uma estrutura única, mas pode ser reutilizado diversas vezes com informações diferentes. Os dados são enviados pelo componente pai por meio das props titulo, autor e categoria.

Dessa forma, caso seja necessário modificar a maneira como os projetos são apresentados, basta realizar a alteração no componente ProjetoCard.vue, fazendo com que a mudança seja refletida em todos os locais em que o componente é utilizado. Esse comportamento demonstra como a utilização de componentes contribui para a reutilização de código, a organização da interface e a facilidade de manutenção da aplicação.

Vantagens

  • Reutilização: Permite utilizar a mesma estrutura visual e lógica em diferentes partes do sistema, podendo receber dados distintos por meio de Props
  • Manutenibilidade: O isolamento de código facilita a identificação e correção de erros sem impactar o resto da aplicação.
  • Composição: Interfaces complexas podem ser divididas e construídas através da união de peças menores (por exemplo, um componente pai gerindo vários filhos).
  • Reatividade simplificada: A gestão do estado da aplicação acompanha perfeitamente a renderização na tela.
🚨⚠️ Atenção

Embora a extração para microcomponentes ajude na organização, isso pode se tornar um trabalho exaustivo caso seja mal planejado. Evite fragmentar partes da interface que não possuem complexidade substancial ou que jamais serão reutilizadas. Ter uma quantidade excessiva de componentes muito pequenos pode, paradoxalmente, dificultar a leitura geral do fluxo do seu código.

📌 Resumindo...

A utilização de componentes no Vue.js permite:

  • construir interfaces dinâmicas por meio de blocos independentes;
  • centralizar HTML, CSS e JS em Single-File Components;
  • compartilhar dados eficientemente entre elementos via Props;
  • gerenciar o estado reativo sem intervenção manual no DOM;
  • garantir a escalabilidade de projetos extensos.
03

Composables (Funções de Composição) no Vue.js

À medida que as aplicações Vue.js crescem, a lógica responsável pelo funcionamento dos componentes pode se tornar cada vez mais complexa. Para evitar a repetição de código e facilitar a organização dessas funcionalidades, o Vue.js oferece os Composables, que permitem separar e reutilizar lógicas entre diferentes partes da aplicação.

O que é?

No contexto das aplicações Vue.js, um Composable (Função de Composição) é uma função que utiliza a Composition API para encapsular e reutilizar uma determinada lógica baseada em estado. Ele permite separar comportamentos que poderiam ficar concentrados dentro dos componentes, tornando o código mais organizado e facilitando sua reutilização em diferentes partes da aplicação.

Os Composables são uma abordagem utilizada no Vue 3 para compartilhar lógica entre componentes, oferecendo uma alternativa aos Mixins utilizados em versões anteriores do Vue. Em termos práticos, um Composable permite separar a lógica de uma funcionalidade da camada de apresentação visual, evitando que o componente fique responsável por concentrar todas as regras e comportamentos da aplicação.

Como funciona?

Diferentemente de um componente, que pode reunir estrutura, lógica e estilos, um Composable é normalmente implementado como uma função em JavaScript ou TypeScript, geralmente em arquivos .js ou .ts separados. Dentro dessas funções, podem ser utilizados recursos da Composition API, como ref(), reactive() e hooks do ciclo de vida, para criar e gerenciar dados e comportamentos reativos.

Por convenção, os nomes dos Composables geralmente começam com o prefixo use, como useProjetos(), useUsuario() ou useFetch(). Quando um componente utiliza um Composable, a função pode retornar dados reativos e métodos que serão utilizados pelo componente, permitindo separar a lógica da estrutura visual.

Quando utilizar?

A criação de um Composable é indicada quando uma determinada lógica precisa ser reutilizada em diferentes componentes ou quando uma funcionalidade possui comportamentos que podem ser separados da interface. Por exemplo, operações relacionadas ao cadastro de projetos, controle de formulários ou comunicação com uma API podem ser organizadas em Composables.

De forma resumida, Composables são utilizados principalmente para compartilhar lógica e comportamento entre diferentes partes da aplicação. Quando a necessidade está relacionada ao compartilhamento da estrutura visual, como HTML e estilos, a criação de componentes reutilizáveis costuma ser uma abordagem mais adequada.

Exemplo prático

Considere uma aplicação destinada ao gerenciamento de projetos de uma feira científica. Nesse contexto, diferentes partes do sistema podem precisar realizar operações relacionadas aos projetos cadastrados. Para evitar que essa lógica seja repetida em vários componentes, podemos criar um Composable responsável por centralizar essas operações.

O arquivo useProjetos.js pode ser definido da seguinte maneira:

import { ref } from 'vue'

export function useProjetos() {

    const projetos = ref([])
    const carregando = ref(false)

    function adicionarProjeto(projeto) {
        projetos.value.push(projeto)
    }
    function removerProjeto(id) {
        projetos.value =
            projetos.value.filter(
                projeto => projeto.id !== id
            )
    }
    return {
        projetos,
        carregando,
        adicionarProjeto,
        removerProjeto
    }
}

Esse Composable pode ser utilizado por um componente responsável pela apresentação dos projetos:

<script setup>
import { useProjetos } from './composables/useProjetos.js'

const {
    projetos,
    adicionarProjeto,
    removerProjeto
} = useProjetos()

function cadastrarProjeto() {
    adicionarProjeto({
        id: 1,
        titulo: 'Sistema de Irrigação Inteligente',
        categoria: 'Tecnologia'
    })
}

</script>

<template>

    <div>

        <h2>Projetos cadastrados</h2>

        <button @click="cadastrarProjeto">
            Cadastrar projeto
        </button>

        <ul>
            <li v-for="projeto in projetos" :key="projeto.id">

                {{ projeto.titulo }} -
                {{ projeto.categoria }}

                <button @click="removerProjeto(projeto.id)">
                        Remover
                </button>
            </li>
        </ul>
    </div>
</template>

Nesse exemplo, a lógica responsável por armazenar, adicionar e remover projetos está concentrada no Composable useProjetos. O componente utiliza essa lógica sem precisar implementar diretamente todas essas operações, ficando responsável principalmente pela apresentação das informações e pela interação com o usuário.

Caso outro componente também precise realizar as mesmas operações, ele poderá utilizar o useProjetos(), evitando a duplicação da lógica.

Vantagens

  • Reaproveitamento de lógica:permite utilizar a mesma lógica em diferentes componentes sem a necessidade de duplicar código.
  • Organização:possibilita separar comportamentos específicos da estrutura visual dos componentes.
  • Facilidade de manutenção:alterações na lógica podem ser realizadas diretamente no Composable, reduzindo a necessidade de modificar vários componentes.
  • Testabilidade:por serem funções independentes, os Composables podem facilitar a realização de testes sobre a lógica que implementam.
  • Composição de funcionalidades:um Composable pode utilizar outros Composables, permitindo organizar funcionalidades maiores em partes menores e reutilizáveis.
  • Integração com TypeScript:quando utilizados com TypeScript, os Composables podem se beneficiar da tipagem estática e da inferência de tipos.
🚨⚠️ Atenção

Embora os Composables sejam úteis para compartilhar lógica, eles não devem ser utilizados para qualquer situação. Criar Composables para funcionalidades muito simples ou que nunca serão reutilizadas pode aumentar desnecessariamente a complexidade do projeto.

Também é importante ter atenção ao gerenciamento do ciclo de vida. Quando um Composable registra eventos, temporizadores ou outros recursos persistentes, é necessário realizar a limpeza adequada quando o componente deixar de ser utilizado. Recursos como onUnmounted() podem ser utilizados para remover listeners e interromper operações que não sejam mais necessárias.

Além disso, quando um Composable utiliza recursos relacionados ao ciclo de vida do componente, ele deve ser chamado durante a execução síncrona do setup() ou do <script setup>, permitindo que esses recursos sejam associados corretamente ao componente.

📌 Resumindo...

O uso de Composables no Vue.js permite:

  • extrair lógicas e comportamentos dos componentes;
  • reutilizar funcionalidades em diferentes partes da aplicação;
  • reduzir a duplicação de código;
  • facilitar a manutenção e os testes;
  • organizar funcionalidades complexas em partes menores;
  • combinar diferentes Composables para construir funcionalidades mais completas.
04

Padrão Container / Presentational no Vue.js

Conforme uma aplicação cresce, seus componentes podem acumular diferentes responsabilidades, como buscar dados, controlar estados e apresentar informações na tela. Para lidar com essa situação, o padrão Container/Presentational propõe uma separação entre a lógica responsável pelo funcionamento da aplicação e a estrutura responsável pela apresentação da interface.

O que é?

O padrão Container/Presentational é uma abordagem que busca separar a lógica responsável pelo funcionamento da aplicação da parte responsável pela apresentação visual. No Vue.js, essa separação pode ser realizada dividindo os componentes de acordo com suas responsabilidades: os Containers ficam responsáveis por dados, estado e comportamentos, enquanto os componentes Presentational concentram a construção da interface.

Essa organização aplica o princípio de Separação de Responsabilidades (Separation of Concerns), tornando cada componente mais específico em sua função e facilitando a manutenção e a reutilização do código.

Como funciona?

O padrão divide a interface em dois tipos principais de componentes:

Componentes Container:

são responsáveis por lidar com dados, estados e comportamentos da aplicação. Podem realizar requisições a APIs, utilizar fontes de dados e definir o que será apresentado. Depois de obter os dados, eles os encaminham para os componentes Presentational por meio de Props e podem receber ações por meio de eventos.

Componentes Presentational:

são responsáveis principalmente pela apresentação das informações recebidas. Eles utilizam Props para receber dados e podem emitir eventos quando o usuário realiza alguma ação, deixando para o componente Container a responsabilidade de decidir como essa ação será tratada.

Dessa forma, o Container concentra a lógica da aplicação, enquanto o Presentational se concentra na construção da interface.

Quando utilizar?

Esse padrão pode ser utilizado quando um componente começa a reunir muitas responsabilidades, misturando a obtenção e manipulação de dados com uma estrutura visual extensa. A separação também pode ser útil quando uma mesma interface precisa ser reutilizada com diferentes fontes de dados ou comportamentos.

Entretanto, não é necessário aplicar essa divisão em todos os componentes. Em aplicações menores ou em funcionalidades simples, separar cada parte em um Container e um Presentational pode aumentar a quantidade de arquivos e a complexidade do projeto.

Exemplo prático

Considere uma aplicação destinada ao gerenciamento de projetos de uma feira científica. Nesse sistema, podemos separar a responsabilidade de obter e controlar os projetos da responsabilidade de apresentá-los na tela.

1. Componente Presentational (ProjetoList.vue)

Esse componente recebe os projetos por meio de Props e fica responsável por apresentar as informações ao usuário:

<script setup>

defineProps({
    projetos: {
        type: Array,
        required: true
    }
})

const emit = defineEmits(['selecionar'])
</script>

<template>
    <ul>
        <li
            v-for="projeto in projetos"
            :key="projeto.id"
        >
            <strong>{{ projeto.titulo }}</strong>
            <span> - {{ projeto.categoria }}</span>

            <button @click="emit('selecionar', projeto.id)">
                Selecionar
            </button>
        </li>
    </ul>
</template>

O componente não precisa saber de onde os projetos vieram nem o que deverá acontecer depois que um projeto for selecionado. Sua responsabilidade é apresentar os dados recebidos e comunicar a interação realizada pelo usuário.

2. Componente Container (ProjetoListContainer.vue)

O Container fica responsável por obter os dados e definir o comportamento da aplicação:

<script setup>

import { ref, onMounted } from 'vue'
import ProjetoList from './ProjetoList.vue'

const projetos = ref([])

onMounted(() => {
    projetos.value = [
        {
            id: 1,
            titulo: 'Sistema de Irrigação Inteligente',
            categoria: 'Tecnologia'
        },
        {
            id: 2,
            titulo: 'Análise da Qualidade da Água',
            categoria: 'Meio Ambiente'
        }
    ]
})

function selecionarProjeto(id) {
    console.log('Projeto selecionado:', id)
}
</script>

<template>
    <ProjetoList
        :projetos="projetos"
        @selecionar="selecionarProjeto"
    />
</template>

Nesse exemplo, o ProjetoListContainer controla os dados e o comportamento relacionado aos projetos, enquanto o ProjetoList concentra apenas a apresentação dessas informações.

A comunicação entre os componentes ocorre por meio de Props, utilizadas para enviar os projetos ao componente filho, e de eventos, utilizados para informar ao Container que o usuário selecionou determinado projeto.

Vantagens

  • Separação de responsabilidades: permite separar a lógica da aplicação da estrutura visual dos componentes.
  • Reutilização: componentes Presentational podem ser utilizados em diferentes contextos, recebendo dados distintos por meio de Props.
  • Organização: facilita a compreensão do código ao definir responsabilidades específicas para cada componente.
  • Manutenção: alterações na apresentação podem ser realizadas sem modificar diretamente a lógica responsável pelos dados.
  • Testabilidade: componentes que se concentram apenas na apresentação podem ser testados de forma mais isolada.
🚨⚠️ Atenção

O padrão Container/Presentational não precisa ser aplicado de maneira rígida em todas as situações. Com a utilização da Composition API e dos Composables no Vue 3, muitas aplicações conseguem separar a lógica da interface sem a necessidade de criar um componente Container específico.

Em determinadas situações, um Composable pode concentrar a lógica de uma funcionalidade e ser utilizado diretamente pelo componente que apresenta os dados. Essa abordagem pode reduzir a quantidade de componentes necessários e evitar uma estrutura excessivamente complexa.

Por isso, a escolha entre utilizar Containers, Composables ou uma combinação das duas abordagens deve considerar a complexidade e as necessidades da aplicação.

📌 Resumindo...

O padrão Container/Presentational permite:

  • separar a lógica da aplicação da apresentação visual;
  • criar componentes focados na exibição das informações;
  • centralizar o gerenciamento de dados e comportamentos nos Containers;
  • facilitar a reutilização e manutenção dos componentes;
  • organizar melhor aplicações com interfaces mais complexas;
  • combinar diferentes abordagens, como Containers e Composables, de acordo com a necessidade do projeto.
05

Padrão Provedor de Dados (Data Provider) no Vue.js

Conforme as aplicações Vue.js se tornam mais complexas, pode surgir a necessidade de compartilhar a mesma lógica de obtenção e gerenciamento de dados entre diferentes interfaces. Nesse contexto, o padrão Data Provider permite separar o fornecimento das informações da forma como elas serão apresentadas ao usuário.

O que é?

O padrão Provedor de Dados (Data Provider) é uma abordagem que busca separar a lógica responsável pela obtenção e gerenciamento de dados da estrutura responsável por apresentá-los na interface. Dessa forma, um componente pode ficar responsável por fornecer as informações, enquanto outros componentes definem como esses dados serão exibidos.

No Vue.js, essa abordagem pode ser implementada por meio de componentes sem renderização (renderless components) e Slots, permitindo que o componente consumidor tenha maior controle sobre a estrutura visual enquanto recebe os dados disponibilizados pelo provedor.

Como funciona?

O componente Data Provider concentra a lógica relacionada aos dados, como chamadas a APIs, controle de carregamento e gerenciamento do estado. Essas informações são disponibilizadas aos componentes consumidores por meio de um .

Através da diretiva v-slot, o componente consumidor pode acessar os dados fornecidos e decidir como apresentá-los. Dessa forma, uma mesma lógica de obtenção de informações pode ser utilizada em diferentes interfaces, sem que seja necessário duplicar o código responsável por buscar e controlar esses dados.

Os Slots do Vue permitem que um componente receba conteúdo definido pelo componente pai. Quando utilizados como slots com escopo, também podem receber dados disponibilizados pelo componente que os contém, permitindo a comunicação entre o provedor e a interface que irá consumir essas informações.

Quando utilizar?

O Data Provider pode ser utilizado quando uma determinada lógica de obtenção e gerenciamento de dados precisa ser compartilhada entre diferentes interfaces. Ele é especialmente útil quando os mesmos dados precisam ser apresentados de maneiras diferentes, dependendo do contexto da aplicação.

Por exemplo, uma aplicação pode obter uma lista de projetos científicos uma única vez e disponibilizar essas informações para diferentes componentes, que poderão apresentá-las como uma lista, tabela ou conjunto de cartões.

Entretanto, esse padrão não precisa ser utilizado em todas as situações. Quando o objetivo principal é apenas reutilizar uma determinada lógica entre componentes, um Composable pode oferecer uma solução mais simples e direta.

Exemplo prático

Considere uma aplicação para gerenciamento de projetos de uma feira científica. Nesse sistema, diferentes partes da aplicação podem precisar acessar a lista de projetos cadastrados. Para evitar que cada componente implemente sua própria lógica de obtenção desses dados, podemos criar um componente responsável por fornecê-los.

1. Componente Provedor (ProjetoDataProvider.vue)

O Data Provider será responsável por armazenar os projetos e controlar o estado de carregamento. Os dados serão disponibilizados para o componente consumidor por meio do :

<script setup>
import { ref, onMounted } from 'vue'

const projetos = ref([])
const loading = ref(true)

onMounted(() => {
    projetos.value = [
        {
            id: 1,
            titulo: 'Sistema de Irrigação Inteligente',
            categoria: 'Tecnologia'
        },
        {
            id: 2,
            titulo: 'Análise da Qualidade da Água',
            categoria: 'Meio Ambiente'
        }
    ]
    loading.value = false
})

</script>

<template>
    <slot
        :projetos="projetos"
        :loading="loading"
    />
</template>

Nesse componente, os dados são mantidos de forma reativa por meio de ref(). O disponibiliza projetos e loading para o componente que utilizar o Data Provider.

2. Componente Consumidor (ProjetoLista.vue)

O componente consumidor utiliza v-slot para acessar os dados fornecidos e define como eles serão apresentados:

<script setup>
import ProjetoDataProvider from './ProjetoDataProvider.vue'
</script>

<template>
    <ProjetoDataProvider v-slot="{ projetos, loading }">

        <p v-if="loading">
            Carregando projetos...
        </p>

        <ul v-else>
            <li
                v-for="projeto in projetos"
                :key="projeto.id"
            >

                <strong>{{ projeto.titulo }}</strong>
                <span> - {{ projeto.categoria }}</span>
            </li>
        </ul>

    </ProjetoDataProvider>
</template>

Nesse exemplo, o ProjetoDataProvider é responsável por fornecer os dados, enquanto o componente consumidor decide como essas informações serão apresentadas. Isso permite que outros componentes utilizem o mesmo provedor e apresentem os projetos de maneiras diferentes, sem precisar repetir a lógica responsável pela obtenção dos dados.

Vantagens

  • Separação de responsabilidades: separa a lógica de obtenção e gerenciamento dos dados da apresentação da interface.
  • Reutilização: permite utilizar uma mesma lógica de fornecimento de dados em diferentes componentes.
  • Flexibilidade visual: diferentes componentes podem apresentar os mesmos dados utilizando estruturas visuais distintas.
  • Organização: evita concentrar a obtenção dos dados e a construção da interface em um único componente.
  • Redução da duplicação: evita que diferentes componentes precisem implementar novamente a mesma lógica de obtenção e gerenciamento das informações.
🚨⚠️ Atenção

O Data Provider não precisa ser utilizado em todas as situações. Com a utilização da Composition API e dos Composables no Vue 3, muitas funcionalidades podem ter sua lógica reutilizada sem a necessidade de criar um componente específico para fornecer os dados.

Por isso, antes de utilizar esse padrão, é importante avaliar a complexidade da aplicação e a forma como a lógica será reutilizada. Em situações mais simples, um Composable pode oferecer uma solução mais direta. Quando a necessidade envolve fornecer dados para diferentes estruturas de interface por meio de Slots, o Data Provider pode ser uma alternativa adequada.

Também é importante considerar que o Data Provider utiliza um componente para encapsular a lógica, enquanto um Composable permite reutilizar essa lógica diretamente dentro dos componentes. O Patterns.dev destaca justamente os Composables como uma alternativa para diversos casos em que o Data Provider poderia ser utilizado.

📌 Resumindo...

O padrão Data Provider permite:

  • separar a obtenção e o gerenciamento dos dados da apresentação da interface;
  • disponibilizar informações para componentes consumidores por meio de Slots;
  • reutilizar uma mesma lógica de fornecimento de dados em diferentes interfaces;
  • reduzir a duplicação de código;
  • permitir que os mesmos dados sejam apresentados de diferentes maneiras;
  • organizar melhor a comunicação entre a lógica de dados e a camada visual.

Padrão Componentes Dinâmicos (Dynamic Components) no Vue.js

À medida que uma aplicação cresce, pode surgir a necessidade de apresentar diferentes conteúdos em uma mesma região da interface, dependendo da interação realizada pelo usuário. Em situações como abas, etapas de formulários e diferentes modos de visualização, seria possível utilizar várias estruturas condicionais para controlar o que será exibido. Entretanto, o Vue.js oferece os Componentes Dinâmicos como uma alternativa mais organizada para realizar essa troca de componentes de forma reativa.

O que é?

O padrão Componentes Dinâmicos (Dynamic Components) é um recurso do Vue.js que permite alternar dinamicamente entre diferentes componentes dentro de uma mesma região da interface. Dessa forma, em vez de definir antecipadamente qual componente será exibido, a aplicação pode determinar qual deles deve ser renderizado de acordo com o estado atual.

Esse recurso é especialmente útil em interfaces nas quais diferentes componentes precisam ocupar o mesmo espaço, como sistemas de abas, etapas de formulários, painéis de informações ou diferentes formas de visualizar um determinado conteúdo.

No Vue.js, essa funcionalidade é realizada principalmente por meio do elemento especial e da propriedade :is, que permite definir qual componente deverá ser apresentado naquele momento.

Como funciona?

O Vue disponibiliza a tag , que pode utilizar a propriedade :is para determinar qual componente será renderizado. O valor utilizado nessa propriedade pode representar o nome de um componente registrado ou o próprio objeto do componente importado.

Quando o valor utilizado em :is é alterado, o Vue atualiza a interface para apresentar o novo componente no mesmo local. Dessa forma, diferentes componentes podem ocupar uma mesma região da tela sem que seja necessário criar uma estrutura extensa de v-if e v-else-if.

Para controlar qual componente será exibido, normalmente utilizamos uma variável reativa. Por exemplo, uma aplicação pode possuir uma variável chamada abaAtual, responsável por armazenar a identificação da aba selecionada. A partir dessa informação, o determina qual componente deverá ser apresentado.

Quando utilizar?

Os Componentes Dinâmicos podem ser utilizados quando diferentes componentes precisam ser exibidos de forma alternativa em uma mesma região da interface. Alguns cenários comuns são:

  • Sistemas de Abas (Tabs): permitem alternar entre diferentes conteúdos de uma página, como informações, avaliações e cronogramas.
  • Assistentes de etapas (Wizards/Steppers): permitem dividir formulários ou processos maiores em diferentes etapas.
  • Diferentes modos de visualização: possibilitam alternar entre componentes que apresentam os mesmos dados de maneiras diferentes
  • Painéis interativos: permitem modificar o conteúdo apresentado de acordo com a opção selecionada pelo usuário.

Entretanto, esse recurso não precisa ser utilizado em todas as situações. Quando a interface possui apenas pequenas diferenças entre os conteúdos apresentados, uma estrutura condicional simples pode ser suficiente. O uso de Componentes Dinâmicos é mais interessante quando existem componentes independentes que precisam ocupar a mesma região da interface.

Exemplo

<script setup>
import { ref } from 'vue'

import Projetos from './components/Projetos.vue'
import Avaliacoes from './components/Avaliacoes.vue'
import Cronograma from './components/Cronograma.vue'

const abaAtual = ref('Projetos')

const abas = {
    Projetos,
    Avaliacoes,
    Cronograma
}

</script>

<template>
    <div>
        <button
            v-for="(_, aba) in abas"
            :key="aba"
            @click="abaAtual = aba"
        >
            {{ aba }}
        </button>

        <component :is="abas[abaAtual]" />
    </div>
</template>

Nesse exemplo, três componentes são importados: Projetos, Avaliacoes e Cronograma. O objeto abas associa cada nome ao respectivo componente, enquanto a variável abaAtual controla qual deles está selecionado.

Quando o usuário clica em uma das opções, o valor de abaAtual é alterado. Como essa variável é reativa, o Vue identifica a mudança e atualiza o , exibindo o componente correspondente.

Essa estrutura pode ser utilizada, por exemplo, em uma plataforma para gerenciamento de projetos de feiras científicas, permitindo que o usuário alterne entre as informações do projeto, suas avaliações e o cronograma sem precisar navegar para uma nova página.

Vantagens

A utilização de Componentes Dinâmicos pode trazer diferentes benefícios para o desenvolvimento de aplicações Vue.js:

  • Organização do código: permite separar diferentes partes da interface em componentes independentes.
  • Flexibilidade: facilita a criação de interfaces que precisam alternar entre diferentes conteúdos.
  • Reutilização: possibilita utilizar uma estrutura de controle comum para alternar entre diferentes componentes.
  • Redução de condicionais: pode evitar estruturas extensas formadas por vários v-if e v-else-if.
🚨⚠️ Atenção

Preservação de Estado

Um ponto importante ao utilizar Componentes Dinâmicos está relacionado à preservação do Melhor experiência de navegação: permite realizar mudanças de conteúdo sem necessariamente alterar a rota da aplicação.

Por padrão, quando um componente dinâmico deixa de ser o componente ativo, ele é desmontado. Consequentemente, estados mantidos dentro daquela instância podem ser perdidos. Esse comportamento é adequado em muitas situações, mas pode não ser desejado quando o usuário precisa retornar ao componente e continuar de onde parou.

Para preservar essas instâncias, o Vue disponibiliza o componente . Quando utilizado ao redor de um componente dinâmico, ele mantém as instâncias inativas em cache em vez de destruí-las, permitindo que seu estado seja preservado enquanto o usuário alterna entre os componentes.

Exemplo

<template>

    <div>

        <button
            v-for="(_, aba) in abas"
            :key="aba"
            @click="abaAtual = aba"
        >
            {{ aba }}
        </button>

        <KeepAlive>

            <component :is="abas[abaAtual]" />

        </KeepAlive>

    </div>

</template>

Nesse caso, ao alternar entre os componentes, o Vue mantém as instâncias inativas em cache. Assim, quando o usuário retorna para uma determinada aba, o estado do componente pode ser preservado em vez de ser iniciado novamente.

Por exemplo, imagine que o componente Avaliacoes.vue possua um formulário parcialmente preenchido. Sem o , a troca para outra aba pode fazer com que a instância seja desmontada. Com o , a instância pode permanecer em cache e o usuário poderá retornar ao componente mantendo seu estado.

É importante observar que o deve ser utilizado de acordo com a necessidade da aplicação, pois ele mantém componentes em cache. O Vue também disponibiliza propriedades como include, exclude e max, que permitem controlar quais componentes serão armazenados e a quantidade máxima de instâncias mantidas em cache.

📌 Resumindo...

Os Componentes Dinâmicos permitem:

  • Alternar entre diferentes componentes utilizando ;
  • Criar sistemas de abas e interfaces interativas sem depender de novas rotas;
  • Evitar estruturas extensas de condicionais para controlar diferentes componentes;
  • Organizar diferentes partes da interface em componentes independentes;
  • Utilizar quando for necessário preservar o estado dos componentes durante a alternância;
  • Criar interfaces mais flexíveis e adaptáveis às interações do usuário.

Padrão Fornecer/Injetar (Provide/Inject) no Vue.js

À medida que uma aplicação Vue.js cresce, a comunicação entre os componentes pode se tornar mais complexa, principalmente quando existe uma grande quantidade de componentes organizados em diferentes níveis de uma hierarquia. Normalmente, quando um componente precisa receber uma informação de seu componente pai, utilizamos props. Entretanto, quando essa informação precisa chegar a um componente que está vários níveis abaixo, pode ser necessário repassá-la por componentes intermediários que não utilizam aquele dado. Nesse contexto, o padrão Provide/Inject oferece uma alternativa para facilitar o compartilhamento de informações entre componentes relacionados na hierarquia.

O que é?

O Provide/Inject é um recurso do Vue.js que permite que um componente ancestral disponibilize valores ou dependências para seus componentes descendentes, independentemente da quantidade de níveis existentes entre eles. Para isso, o componente responsável por disponibilizar a informação utiliza provide(), enquanto o componente que necessita dela utiliza inject().

Essa abordagem ajuda a evitar o problema conhecido como prop drilling, que ocorre quando uma propriedade precisa ser passada por vários componentes intermediários apenas para chegar até um componente mais distante. Nesse caso, os componentes intermediários precisam receber e repassar a informação mesmo sem utilizá-la diretamente.

Dessa forma, o Provide/Inject permite que o componente que possui a informação e o componente que precisa consumi-la se comuniquem de maneira mais direta, sem a necessidade de utilizar props em todos os níveis da hierarquia.

Como funciona?

O funcionamento do Provide/Inject ocorre por meio de duas funções complementares:

provide()

utilizada pelo componente ancestral para disponibilizar uma informação ou dependência. Ela recebe uma chave que identifica o valor e o próprio valor que será fornecido.

inject()

utilizada pelo componente descendente para acessar uma informação que foi disponibilizada por algum componente ancestral, utilizando a mesma chave.

Quando um componente utiliza inject(), o Vue procura pela chave informada na hierarquia de componentes. Caso existam vários componentes ancestrais fornecendo valores com a mesma chave, será utilizado o valor fornecido pelo ancestral mais próximo.

Um valor fornecido também pode ser reativo. Por exemplo, ao disponibilizar um objeto ref(), o componente que realiza o inject() recebe essa referência e mantém a conexão reativa com o componente que forneceu o valor. Dessa forma, alterações realizadas no estado reativo podem ser refletidas nos componentes que utilizam essa informação.

Além do fornecimento realizado entre componentes, o Vue também permite utilizar app.provide() no nível da aplicação. Nesse caso, a dependência disponibilizada pode ser acessada pelos componentes pertencentes àquela aplicação. Esse recurso é especialmente útil em situações como a criação de plugins e o compartilhamento de determinadas configurações da aplicação.

Quando utilizar?

O Provide/Inject pode ser utilizado quando uma informação precisa ser compartilhada entre componentes que estão distantes na hierarquia e a utilização de props resultaria em uma quantidade desnecessária de repasses entre componentes intermediários.

Alguns exemplos de utilização são:

  • Configurações compartilhadas: informações que precisam estar disponíveis para diferentes componentes de uma determinada parte da aplicação.
  • Temas da interface: informações relacionadas ao modo de exibição, como configurações de tema.
  • Preferências da aplicação: configurações que podem ser utilizadas por diferentes componentes.
  • Dependências de componentes: serviços ou objetos que precisam ser disponibilizados para diferentes descendentes.
  • Plugins: valores e serviços que precisam estar disponíveis em diferentes componentes da aplicação.

Entretanto, o Provide/Inject não deve substituir o uso de props em todas as situações. Quando a comunicação ocorre diretamente entre um componente pai e um componente filho e a informação possui uma relação clara com essa comunicação, o uso de props continua sendo uma alternativa simples e explícita.

Da mesma forma, em aplicações que necessitam de um gerenciamento mais amplo e estruturado do estado da aplicação, pode ser mais adequado utilizar uma solução específica de gerenciamento de estado. O Provide/Inject é mais indicado para disponibilizar dependências ou informações dentro de uma determinada hierarquia de componentes ou, quando necessário, no nível da aplicação.

Exemplo

Considere novamente o contexto de uma plataforma para gerenciamento de projetos de uma feira científica. Imagine que o sistema possua uma informação chamada “Tema Anual da Feira”, que precisa ser apresentada em um componente responsável pelos detalhes de um projeto.

A estrutura da aplicação pode ser representada da seguinte forma:

App.vue → PainelProjetos.vue → ListaProjetos.vue → DetalhesProjeto.vue

Nesse cenário, o DetalhesProjeto.vue está distante do App.vue. Caso utilizássemos apenas props, seria necessário passar o temaFeira por cada componente intermediário, mesmo que eles não utilizassem diretamente essa informação.

Com Provide/Inject, o App.vue pode fornecer a informação e o DetalhesProjeto.vue pode acessá-la diretamente.

O componente ancestral (App.vue) fornece o dado:

<script setup>

import { provide } from 'vue'
import PainelProjetos from './components/PainelProjetos.vue'

provide(
    'temaFeira',
    'Inovações Sustentáveis e Meio Ambiente'
)
</script>

<template>

    <div>

        <h1>Sistema da Feira Científica</h1>

        <PainelProjetos />

    </div>

</template>

Nesse componente, a função provide() disponibiliza o valor associado à chave temaFeira. Todos os componentes descendentes dessa hierarquia poderão acessar essa informação utilizando a mesma chave.

O componente intermediário (PainelProjetos.vue) não precisa repassar o dado:

<script setup>
import ListaProjetos from './ListaProjetos.vue'

</script>

<template>

    <div class="painel">

        <ListaProjetos />

    </div>

</template>

O PainelProjetos.vue não precisa receber temaFeira por props e nem repassá-lo para ListaProjetos.vue, pois ele não utiliza essa informação.

O componente descendente (DetalhesProjeto.vue) injeta o dado:

<script setup>
import { inject } from 'vue'

const temaAnual = inject('temaFeira')

</script>

<template>

    <div class="detalhes-projeto">

        <h2>Análise da Qualidade da Água</h2>

        <p>

            <strong>Tema da Feira:</strong>
            {{ temaAnual }}

        </p>

    </div>
</template>

Nesse caso, o DetalhesProjeto.vue utiliza inject() para acessar diretamente o valor fornecido pelo App.vue. Os componentes intermediários não precisam conhecer ou manipular essa informação.

Esse exemplo demonstra como o Provide/Inject pode evitar o prop drilling, mantendo os componentes intermediários livres de propriedades que não fazem parte de suas responsabilidades.

Vantagens

A utilização do Provide/Inject pode apresentar algumas vantagens no desenvolvimento de aplicações Vue.js:

  • Redução do Prop Drilling: evita a necessidade de passar propriedades por vários níveis de componentes que não utilizam diretamente aquela informação.
  • Comunicação entre componentes distantes: permite que componentes descendentes acessem informações disponibilizadas por componentes ancestrais sem depender de vários repasses de props.
  • Organização do código: reduz a quantidade de propriedades e informações que precisam ser transportadas pelos componentes intermediários.
  • Reutilização de dependências: permite disponibilizar determinados serviços, configurações ou objetos para diferentes componentes de uma mesma hierarquia.
  • Integração com plugins: o app.provide() permite disponibilizar dependências no nível da aplicação, sendo útil para a construção de plugins.
⚠️ Atenção

uso consciente

Embora o Provide/Inject facilite o compartilhamento de informações, seu uso deve ser realizado de maneira consciente. Diferentemente das props, o componente que recebe uma informação por inject() não deixa tão evidente, apenas pela estrutura do componente, de onde aquele valor está sendo fornecido.

Em aplicações maiores, isso pode dificultar o rastreamento da origem de determinadas informações e tornar a manutenção mais complexa caso existam muitos provedores espalhados pela aplicação.

Outro ponto importante está relacionado às chaves utilizadas para identificar as dependências. Em exemplos simples, é comum utilizar strings, como provide('temaFeira', valor). Porém, em aplicações maiores ou bibliotecas reutilizáveis, o Vue recomenda o uso de Symbol como chave de injeção para reduzir a possibilidade de conflitos entre diferentes dependências.

Por isso, o Provide/Inject deve ser utilizado principalmente quando existe uma necessidade real de compartilhar uma dependência entre componentes relacionados. Quando a comunicação é simples e direta entre pai e filho, o uso de props continua sendo uma opção mais explícita e fácil de compreender.

📌 Resumindo...

A utilização do padrão Provide/Inject no Vue.js permite:

  • evitar a passagem repetitiva de dados por vários níveis de componentes (prop drilling);
  • disponibilizar informações de um componente ancestral diretamente para seus descendentes;
  • compartilhar configurações e dependências entre diferentes componentes;
  • utilizar app.provide() para disponibilizar dependências no nível da aplicação;
  • manter valores reativos compartilhados entre o componente provedor e seus consumidores;
  • facilitar a comunicação entre componentes distantes dentro de uma mesma hierarquia.
08

Padrão Gerenciamento de Estado (State Management) no Vue.js

À medida que uma aplicação Vue.js cresce, diferentes componentes podem precisar acessar ou modificar as mesmas informações. Quando esses componentes não possuem uma relação direta de pai e filho, compartilhar esses dados utilizando apenas props e eventos pode tornar o código mais complexo. Nesse contexto, o Gerenciamento de Estado permite organizar as informações compartilhadas em uma estrutura centralizada, facilitando seu acesso e manutenção.

O que é?

O Gerenciamento de Estado (State Management) é uma abordagem utilizada para organizar e controlar dados que são compartilhados entre diferentes partes de uma aplicação. Em vez de manter determinadas informações espalhadas pelos componentes, esses dados podem ser centralizados em uma estrutura chamada Store.

A Store funciona como um local central para armazenar o estado compartilhado e os comportamentos relacionados a ele. Dessa forma, diferentes componentes podem acessar as mesmas informações e reagir às suas alterações sem precisar estabelecer uma comunicação direta entre si.

No ecossistema Vue.js, o Pinia é a biblioteca recomendada para implementar o gerenciamento de estado em novas aplicações. Ele fornece recursos para organizar o estado, os valores derivados e as ações relacionadas aos dados da aplicação. (pinia.vuejs.org)

Como funciona?

No Pinia, uma Store pode ser organizada principalmente em três partes:

  • State (Estado): representa os dados armazenados na Store, como uma lista de projetos, usuários ou itens favoritos.
  • Getters: permitem obter valores derivados do estado, funcionando de maneira semelhante às propriedades computadas (computed properties).
  • Actions (Ações): são métodos que concentram comportamentos relacionados ao estado, podendo conter regras de negócio e também operações assíncronas, como chamadas para uma API. (pinia.vuejs.org)

Os componentes da aplicação podem utilizar uma mesma Store para acessar seus dados e executar suas ações. Como o estado é reativo, alterações realizadas na Store podem ser refletidas automaticamente nos componentes que utilizam essas informações.

Quando utilizar?

O Gerenciamento de Estado é indicado quando determinadas informações precisam ser compartilhadas entre diferentes componentes ou áreas da aplicação. Alguns exemplos são:

  • Informações do usuário: dados relacionados ao usuário autenticado e ao seu perfil.
  • Projetos compartilhados: informações que precisam ser utilizadas em diferentes partes do sistema.
  • Itens favoritos: dados modificados em uma tela e apresentados em outra.
  • Configurações da aplicação: preferências utilizadas por diferentes componentes.

Entretanto, nem todo dado precisa ser armazenado em uma Store. Informações utilizadas exclusivamente por um componente, como o controle de abertura de um menu ou o conteúdo temporário de um campo de busca, podem permanecer no estado local utilizando recursos como ref() ou reactive().

Exemplo prático

Voltando ao contexto da nossa plataforma para gerenciamento de projetos de uma feira científica, imagine que os avaliadores possam favoritar projetos para analisá-los posteriormente.

Nesse cenário, o número de projetos favoritos pode ser apresentado no cabeçalho da aplicação, enquanto o botão para favoritar um projeto está localizado no card de cada projeto. Como esses componentes podem estar em diferentes partes da aplicação, uma Store pode centralizar essas informações.

Criando a Store (stores/favoritos.js)

import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useFavoritosStore = defineStore('favoritos', () => {

    const projetosFavoritos = ref([])

    const totalFavoritos = computed(() => {
        return projetosFavoritos.value.length
    })

    function adicionarFavorito(projeto) {

        const jaFavoritado = projetosFavoritos.value
            .some(p => p.id === projeto.id)

        if (!jaFavoritado) {

            projetosFavoritos.value.push(projeto)

        }
    }

    return {
        projetosFavoritos,
        totalFavoritos,
        adicionarFavorito
    }

})

Nesse exemplo, projetosFavoritos representa o State, enquanto totalFavoritos funciona como um valor derivado por meio de computed(). A função adicionarFavorito() representa uma Action, responsável por adicionar um projeto à lista e evitar registros duplicados.:

Utilizando a Store no cabeçalho (Cabecalho.vue)

<script setup>
import { useFavoritosStore } from '../stores/favoritos'

const favoritosStore = useFavoritosStore()

</script>

<template>

    <header>

        <h1>Feira Científica</h1>

        <span>

            Projetos Favoritos:
            {{ favoritosStore.totalFavoritos }} ⭐

        </span>

    </header>

</template>

O cabeçalho acessa a Store para apresentar a quantidade atual de projetos favoritos.

Utilizando a Store no card do projeto (ProjetoCard.vue)

<script setup>

import { useFavoritosStore } from '../stores/favoritos'

defineProps({
    projeto: {
        type: Object,
        required: true
    }
})

const favoritosStore = useFavoritosStore()

</script>


<template>

    <div class="projeto-card">

        <h2>{{ projeto.titulo }}</h2>

        <button
            @click="favoritosStore.adicionarFavorito(projeto)"
        >
            Favoritar Projeto
        </button>

    </div>

</template>

Nesse componente, a mesma Store é utilizada para executar a Action adicionarFavorito(). Quando o usuário seleciona o botão, o projeto é adicionado ao estado compartilhado. Como totalFavoritos depende desse estado, o número apresentado no cabeçalho é atualizado automaticamente.

Dessa forma, o cabeçalho e os cards dos projetos não precisam estabelecer uma comunicação direta, pois ambos utilizam a mesma Store para acessar e modificar as informações relacionadas aos favoritos.

Vantagens

A utilização do Gerenciamento de Estado pode trazer diferentes benefícios:

  • Centralização do estado: reúne informações compartilhadas em uma estrutura central.
  • Redução da comunicação entre componentes: diminui a necessidade de passar dados por diversos níveis de props e eventos.
  • Organização da lógica: permite concentrar comportamentos relacionados aos dados em Stores específicas.
  • Reatividade: alterações no estado compartilhado podem ser refletidas automaticamente nos componentes que utilizam essas informações.
  • Facilidade de manutenção: mantém dados e comportamentos relacionados organizados, facilitando a evolução da aplicação.
🚨⚠️ Atenção: Evite o uso excessivo de Stores

Nem todas as informações da aplicação precisam ser armazenadas em uma Store. Utilizar o gerenciamento de estado para dados estritamente locais pode aumentar desnecessariamente a complexidade do sistema.

Por exemplo, o estado responsável por controlar a abertura de um menu dropdown ou o conteúdo temporário de um campo de pesquisa normalmente pode permanecer dentro do próprio componente. A Store deve ser utilizada quando existir uma necessidade real de compartilhar determinado estado entre diferentes partes da aplicação.

📌 Resumindo...

A utilização do padrão de Gerenciamento de Estado no Vue.js permite:

  • centralizar dados compartilhados em uma Store;
  • disponibilizar informações para diferentes componentes da aplicação;
  • reduzir a necessidade de utilizar diversos níveis de props e eventos;
  • organizar comportamentos relacionados ao estado compartilhado;
  • derivar informações de forma reativa por meio dos Getters;
  • utilizar Actions para executar comportamentos relacionados aos dados;
  • utilizar o Pinia para estruturar o gerenciamento de estado da aplicação.

Considerações Finais

Chegamos ao fim da nossa jornada pelos padrões e abordagens de projeto aplicados ao ecossistema Vue.js. Ao longo desta cartilha, exploramos diferentes formas de estruturar aplicações, desde o uso do <script setup>, a componentização e a criação de Composables, até abordagens voltadas para a organização da comunicação, do fornecimento de dados e do gerenciamento de estado.

Também conhecemos os Componentes Dinâmicos, o Provide/Inject, o padrão Container/Presentational, o Data Provider e o State Management. Cada uma dessas abordagens apresenta diferentes possibilidades para solucionar problemas que podem surgir durante o desenvolvimento de aplicações, contribuindo para um código mais organizado, reutilizável e de fácil manutenção quando utilizadas de maneira adequada.

No entanto, uma das principais lições sobre padrões de projeto e arquitetura de software é compreender quando utilizá-los e quando não utilizá-los. Como apresentado no início desta cartilha, padrões são soluções desenvolvidas para lidar com problemas recorrentes. Quando uma aplicação é simples e não apresenta o problema que determinado padrão busca solucionar, adicionar estruturas ou abstrações desnecessárias pode aumentar a complexidade do código em vez de melhorá-lo.

Por isso, conhecer diferentes padrões não significa utilizá-los sempre. O desenvolvimento de software exige análise e senso crítico para escolher a solução mais adequada para cada situação. Muitas vezes, a alternativa mais simples será também a mais eficiente.

Dessa forma, esperamos que esta cartilha tenha contribuído para ampliar sua compreensão sobre a organização de aplicações Vue.js e que os conhecimentos apresentados possam servir como ponto de partida para novos estudos e projetos. Mais importante do que memorizar padrões é compreender os problemas que eles solucionam e desenvolver a capacidade de escolher conscientemente a abordagem mais adequada para cada contexto.

📌 Lembre-se

Um bom projeto não é aquele que utiliza o maior número de padrões, mas aquele que utiliza as soluções adequadas para seus problemas.

Próximos Passos

O aprendizado em desenvolvimento de software é contínuo. Após conhecer os conceitos apresentados nesta cartilha, existem diversos caminhos que podem ser explorados para aprofundar seus conhecimentos em Vue.js e ampliar suas habilidades no desenvolvimento de aplicações.

  • Nuxt.js e Renderização do Lado do Servidor (SSR)

    • Explore o Nuxt.js, framework baseado em Vue.js, para conhecer conceitos como renderização do lado do servidor (SSR), geração de sites estáticos (SSG), roteamento baseado em arquivos e otimização de aplicações.

  • Roteamento com Vue Router

    • Aprofunde seus conhecimentos sobre o Vue Router, aprendendo a estruturar aplicações de página única (SPAs), trabalhar com diferentes rotas, controlar acesso a determinadas páginas e utilizar técnicas como carregamento sob demanda (lazy loading).

  • Testes Automatizados

    • Conheça ferramentas como Vitest e Vue Test Utils para desenvolver testes automatizados para componentes, Composables e outras partes da aplicação. A utilização de testes contribui para identificar problemas e proporciona maior segurança durante alterações e refatorações do código.

  • Aprofundamento no Ecossistema Vue.js

    • Continue acompanhando a documentação oficial e as atualizações do ecossistema Vue.js. Novos recursos, bibliotecas e práticas de desenvolvimento surgem constantemente, tornando a atualização contínua uma parte importante da formação de qualquer desenvolvedor.
